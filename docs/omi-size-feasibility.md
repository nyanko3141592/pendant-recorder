# Omiサイズへ向けた電池・機構・ファームの再検討

2026-10-24。最新ユーザー指示: Omiサイズを狙い、ファームの省電力化まで含めて再検討する。これは次版の成立条件を定める調査であり、Rev Cの回路・発注状態を置き換えない。16時間の連続録音、USB-C、36時間以上の保存、暗号化、無はんだ組立を維持する。

## 結論と前案の制約

Omi同等の約25〜25.5mm径・15mm厚を次版の収納目標にする。円形そのものは必須ではない。到達済みの寸法ではない。

Rev Cの23.8×34×14mmは、完成電池DTP401525の最大15.5×27×4.2mm、長い付属リード、PHコネクタを維持した結果。27mm長の電池は25.5mm径のケースに平置きで入らない。ファーム変更だけではこの制約は解消しない。

Omiの公開BOMにはGRP1654M1-1C-1S1P、150mAh、D16×H6.1mm、32AWG・線長6mmのカスタム電池が記載されている。基板にはGLF73910保護ICもある。従って、この電池の寸法を「PCM・NTC・コネクタを内蔵した完成パック寸法」と解釈してはいけない。

メーカーのGRP1654M1単セルは150mAh、直径16mm、厚さ5.4mm。容量を110mAhから減らさず、形状を変える方向が第一候補になる。ただし小ロットの完成パック価格・MOQ・納期・輸送・端子仕様は未確認。裸セルをユーザーがはんだ付けする案にはしない。

## 機構の成立条件

- 外径25.5mm、壁厚1mmと仮定すると内径23.5mm。円形PCBの面積上限は約434mm²で、現21×31mm=651mm²より約33%減る。固定、USB開口、配線逃げを引く前の上限である。
- 現21×31mm PCBはそのまま入らない。PCB外形、実装面、部品パッケージ、USB位置を再配置する。
- 電池はPCBと厚み方向に重ねる。参考の厚み配分は底1.0＋電池包絡6.1＋絶縁/逃げ0.5＋裏面部品1.1＋PCB0.8＋表面USB等3.2＋蓋1.0=13.7mm。**電池完成品/USB実装高さ/公差未確定の予算で、収納検証ではない。** PHの5mm高さを残すとこの予算を超える。
- 小型コネクタは電池と平面で重ならない位置に置く。完成短尺ハーネス、PCM、NTCを含む実物の嵌合寸法が必要。極性だけでなく抜け止めと線材曲げも確認する。
- USB-Cの開口をケース外周に出す。内側のバッテリーとの干渉、ケーブル挿入力、マイク音道、固定爪、ストラップを全て最終外形に含める。
- Omiは専用充電台を使うため、USB-Cレセプタクルを内蔵する本案の方が収納条件は厳しい。

## 16時間を成立させる電流

以下は電池端子での平均電流。公称容量の70%を使用可能と仮定した逆算であり、消費電流の予測ではない。70%は低温、劣化、終止電圧を保証する値でもない。

| 容量 | 16hの電流上限 | 20hの電流上限 |
|---|---:|---:|
| 74mAh | 3.24mA | 2.59mA |
| 108mAh | 4.73mA | 3.78mA |
| 現110mAh | 4.81mA | 3.85mA |
| 145mAh | 6.34mA | 5.08mA |
| 第一候補150mAh | 6.56mA | 5.25mA |

150mAhで平均5mAにできれば計算上21h、6mAなら17.5h、7mAでは15h。次版の開発目標は**平均5mA以下**とする。実測前に16h達成と表示しない。現3.3V LDOのドロップアウトで使い残す容量を放電試験で調べ、必要なら降圧/昇降圧とUSB電源分離を面積込みで比較する。

再計算: `python3 hardware/power-study/budget.py`。36hのIMA-ADPCM音声本体は約1.040GB。4GBの容量枠は維持し、ファイル・暗号化・FSの余白を別途評価する。

## 実装する省電力の順番

現firmwareはESP32スタブで、STM32録音ファームは未実装。既存の動作済み実装を最適化済みと扱わない。

1. **常時取り込み、CPUは休止:** ADF1＋LPDMAでPCMをSRAM4の二重バッファへ取り込み、CPUはStop2へ。LPDMAが使えるSRAM4のサイズ・配置・保持設定をU535の資料とリンカで確定する。総RAM274KBを全て低電力DMA領域と数えない。割込みごとに連番とオーバーランを記録する。
2. **ブロック単位で処理:** 必要時だけ起床してIMA-ADPCM、標準ageのストリーム暗号化、書込みを実行。処理時間と最大割込み遅延を測り、最悪条件でも次のバッファを落とさない。独立ageファイルごとの鍵交換・ヘッダ処理も電流に含める。
3. **SDの細切れアクセスを減らす:** 複数セクタをまとめて書き込み、待ち時間はDMA/割込みでCPUを休ませる。Rev CのSPI1はStop2自律SPI3とは別物。SPI1の保存中もStop2で動くとは仮定しない。最初は録音中のSD電源を維持してアイドル電流を測定する。電源断はflush、busy解除、再初期化、耐電断試験が成立した後の比較対象とする。
4. **表示/デバッグを間欠化:** LEDは短い状態表示、常時UARTログを停止、未使用クロック停止、電池ADCは低頻度。録音開始/異常をユーザーが確認できることは維持する。
5. **無音でも録音:** AADでマイクを止めて時間を稼ぐ方式は16h連続録音の合格には使わない。無音でファイルを区切る処理と音声を捨てる処理は分ける。

RAMのバッチを大きくすると未確定音声の損失が増える。短い独立IMA-WAVをage v1で逐次確定し、平文SD一時ファイルを作らない。確定済み区間回収と途中区間の認証失敗検出を試験し、未実測の損失秒数は保証しない。

## 次版へ進める判定

1. 150mAh丸形セル＋保護＋NTC＋短尺完成ハーネスのサンプル調達条件と寸法図を取得。問い合わせは未送信。少量で入手できなければ既製完成パックの形状を再比較する。
2. 実フットプリントで約23mm級外形のPCB配置を試行。PH廃止に加えTSSOPレベル変換の小型パッケージをJLC実装条件込みで比較。BGA/WLCSP採用は受理/費用/配線が成立してから決める。
3. 既存の大きい電気検証基板でもよいので、常時録音→暗号保存の全経路を動作させる。PPK2等で電池端子の積算電荷とSDピーク電流・電圧降下を測る。マイクのみ、圧縮追加、暗号追加、SD追加の差分を記録する。
4. 容量70%の逆算から実電池の放電曲線へ置換。16h連続音声の復号/サンプル数、36h保存、充電中録音、ランダム電源断、3OS同期が合格してから仕様確定する。

既存Rev CのDRC/未接続/発注不可は維持。この検討だけでRev Dの発注データを作ったことにはしない。

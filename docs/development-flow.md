# v1から製品までの開発フロー

基本方針は[決定0001](decisions/0001-product-and-v1.md)。回路とファームを同じ検証サイクルで進め、受領後の手はんだをなくす。発注待ち期間にも実装を進める。

| 段階 | 作業・成果物 | 次へ進む条件 |
|---|---|---|
| 1 調達成立 | メーカー型番・JLC部品番号・在庫確認日・代替・価格・数量をBOMへ。電池と完成プログラマ/ケーブル/治具も購入表へ | 基板上の全品目と電池・NTC・治具について手はんだ工程なし。未一致/TBDを残さない |
| 2 発注設計 | 電源/端子/フットプリント監査、音孔/LED/ボタン/電池端子配置、配線、ケース干渉、公差確認 | ERC/DRC未解決なし、未接続なし、電池/ケーブル/治具の実寸整合。例外は根拠付きレビュー |
| 3 発注リリース | Gerber/穴/BOM/CPL/組立図/検査要求/commit/ハッシュを固定。JLC実装プレビュー・見積り・全品目実装を確認 | 支払前に対象版・完成数量・費用・納期・未検査範囲を提示。小ロットの電気検証用として注文 |
| 4 ファーム・Mac実装 | 回路監査中にボード定義と状態機械を着手。発注待ちに録音/ADPCM/FAT/MSC/表示/時刻とMacコピーを実装 | 対象MCU用の再現可能なビルド・バイナリ・書込み手順。ESP32スタブを完成扱いしない |
| 5 受領・初回通電 | 外観/短絡確認、電流制限付き通電、各電源、SWD、SD、マイク、USB、充電/NTCを段階確認 | 異常発熱・過電流等があれば停止。測定値・試料ID・写真・FW版を記録 |
| 6 統合・連続試験 | 下記検証表を実行。平均/ピーク電流、録音欠落、転送、電池、温度を測定 | 24時間の有効録音を確認。失敗は修正対象として改版へ戻す |
| 7 v1判定 | 試験結果、既知問題、次版への修正、組立再現性をまとめる | 別の人が同じ買物・無はんだ手順で検証できる。未達を隠さず次版へ |
| 8 製品化 | ケース/装着/耐久/量産検査/ファーム更新/復旧/説明書/サポートを仕上げる | 販売地域ごとの適用要件・電池輸送・表示等を専門確認し、販売可否を判定。v1合格と販売承認は別 |

## v1試験の最小セット

- 連続録音: 無音保存省略をオフにして24時間。ファイル数・時刻・再生可能性・欠落を確認。電池端の平均電流2mA目標も別記し、24時間達成だけで電流目標達成としない。
- 電源: 実電池の終止近く、SD書込みピーク、USB挿抜、充電中録音、低電圧時のファイル確定。
- 充電/温度: 電流・電圧・終止・NTC断線/短絡と熱接触。メーカー範囲を満たすか確認。試験条件は事前に定義する。
- USB: 接続だけでは充電のみ、短押しで録音状態不変、同期操作時に録音停止/FS解放、MSC中にFWがSDへ触らない。
- 回復: 正常取り外し、転送中切断、電源断、満杯、破損ファイル。過去の正常録音を巻き込まない。自動削除はしない。
- 音響: 首掛け・服擦れ・小声・通常会話・騒音。合意を得た試験素材か合成音を用い、公開ログには機密録音を入れない。
- Mac: コピーのハッシュ検証、重複取込み回避、処理再開、モデル導入後オフライン動作、外部送信オフを確認。
- 組立: 電池・NTC接触・ケース・書込み・測定まで、はんだごて/圧着工具なしで完了する。

## 記録と改版

`docs/validation/`に空の試験票を置く。実施した試験だけ日付と試料IDで複製する。各回、PCB版/製造ロット/FW commit/アプリ版/電池/治具/機器/条件/測定値/合否/証拠/再現手順を記録。机上計算・シミュレーション・実測を混ぜない。

発注済み製造データは上書きせず、次版ディレクトリへ分ける。販売候補版はクリーンcheckoutからビルドできることを確認し、ソース・依存バージョン・バイナリ・SHA256・組立/書込み手順・試験結果をタグ付きリリースに揃える。現時点では発注リリースを作らない。

# 0004 — ハードウェア中心のv1と同期後の自動整理

2026-10-24。最新ユーザー指定。以前の「自動削除は初期値オフ」「無線MCUは比較のみ」を、以下の範囲で更新する。

## 提供する価値

小型で装着しやすく、長時間の音声を欠落しにくい形で記録し、登録鍵を持つPCへ取り出せるハードウェアを販売する。回路・機構・ファーム・相互運用仕様を公開する。AI機能や用途別アプリを囲い込まない。公式は最低限の同期/復号/音声出力CLIと互換性試験を提供し、第三者アプリを使えるようにする。

## v1の仕様案（測定済み製品仕様ではない）

| 項目 | 要件/目標 |
|---|---|
| 電池 | 無充電で連続24時間超を必須合格条件。30〜36時間は努力目標。既製保護付き110mAhを維持してまず評価 |
| 保存 | 圧縮音声36時間以上。4GBを第一候補。16kHz mono IMA-ADPCMで36h約1.04GB＋標準暗号化/ファイル管理分 |

## Bluetoothと新回路

ユーザーはBluetooth対応MCUへの設計変更を許可。新Rev BはnRF52840を第一候補にUSB/PDM/SPI SD/暗号化を設計する。具体パッケージと電源構成は部品調達・必要端子・電流・面積の照合で確定する。STM32 Rev Aを上書きして同じ回路と扱わない。

v1ではUSBを使い、Bluetooth動作は必須でない。アンテナを省略することは許容されたが、**アンテナ/RFを載せない基板は後日ソフトだけでBluetoothを使えない**。無線を使うにはRF部品の実装や基板改版が必要になり得る。ソフト更新だけで対応したい場合はアンテナを含む実装を初回から完了する必要がある。手元での後付けはんだは解決策にしない。商品表示は無線未検証/未実装の段階で「Bluetooth対応録音機」としない。

新回路への変更で、SDMMC→SPI、クロック、電源、書込み治具、マイク接続、暗号実装、RAM/Flashを再監査。既存の2mAは目標であり、nRFで達成した電流ではない。既存A1のERC合格をRev Bへ流用しない。

## 同期後削除の条件

1. 対象の録音ID・元暗号文ハッシュ・サイズを記録してPCへコピーする。
2. 登録鍵で標準形式の認証/復号を完了し、有効サンプル数を含むWAV検査を行う。
3. PCの最終出力へ確定し、読み戻し/ハッシュ確認、OSの永続化処理の成功を確認して受領記録を保存する。保存先が平文であることを説明する。PC自体の故障まで保護する独立バックアップではない。
4. 現在マウントしている正しい本体上で、録音ID・内容が一致するファイルだけ削除する。ディレクトリ一括削除・名前だけの一致・サイズだけの一致・シェルワイルドカード削除は禁止。
5. MSC中はホストだけがFSを操作。FWが同時に削除しない。切断後に容量とFS状態を再取得し、同期前の録音状態へ戻す。

中断時は保存記録と内容を再照合し、再実行で安全に続ける。復号鍵なし、改ざん、ディスク満杯、未完了録音は自動削除しない。全件削除/古い順上書きは今回の許可に含めない。満杯では表示して停止し、未同期録音を勝手に上書きしない。手動ファイルコピーでは受領を確認できないため、自動削除しない。公式CLIと第三者ツールに同じ条件を公開する。

## 区切りと録音継続

無音で区切る目的は、後段で扱いやすい音声にすること。無音と判定した音を捨てることではない。録音中は前後サンプルを保持し、区切り境界で欠落/重複がないことを検証する。短い電源断対策区間は従来通り独立して確定し、PCへの取出し時に無音区切りのWAVへまとめる方式を第一評価案にする。区切りの判定は軽量でよく、ノイズ除去や意味解析は行わない。

区切り長・無音閾値・無音継続時間・最大出力長は未確定。検証用の固定時間分割を必ず残す。PC側での無音区切りは取り出し時の任意設定とし、複雑な処理を必須にしない。

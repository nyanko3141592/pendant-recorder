# 0013: 共通ファームと初回公開鍵登録

日付: 2026-10-28

状態: **共通ファーム・HID・write-once flash実装済み、実機3 OS/電源断検証前**

## 問題

購入者ごとのage公開鍵をコンパイル時に埋め込む方式では、購入者ごとに別バイナリと別書込み注文が必要になる。これはJLCPCBで同一ファームを一括書込みする量産構成と両立しない。また、録音用MSCをPCから書込み可能にすると、OSの自動メタデータ書込み、フォーマット、誤操作により暗号文の唯一のコピーを破損できる。

## 決定

1. JLCPCBには全個体で同一の製品ファームを書き込む。製造データへ購入者の公開鍵・秘密鍵を含めない。
2. 未登録状態では録音を開始せず、平文へフォールバックしない。USB-C接続時だけ初回登録interfaceを有効にする。
3. 購入者PCで生成したage X25519公開recipientだけを、OS標準driverで扱えるUSB HID feature/output reportにより登録する。秘密鍵はPCから出さない。登録要求だけでは確定せず、本体ボタンを連続2秒以上押している間だけ一度の登録要求を受理する。
4. 登録値はMCU内部flashの予約領域へ、version、CRC、commit markerを持つ二段階commitで保存する。STM32U5の128bit書込み単位に合わせ、commit markerは本文と別quad-wordに置く。電源断で半端な鍵を有効扱いしない。
5. 初回登録は未登録個体に一度だけ許可する。登録後の変更・消去は通常USB操作では許可しない。再登録は別途定義する物理的service手順が完成するまで製品機能にしない。
6. 録音ストレージのMSC LUNは常にread-onlyとし、公開鍵登録に流用しない。
7. 登録後は公開鍵fingerprintをHIDで読み戻し、PC側が送信値と一致確認する。秘密鍵や平文音声を返さない。
8. 検証済み録音の削除はMSC書込みではなくHIDで生成ID範囲を予約する。HIDコマンドだけでは受理せず、本体ボタンを連続2秒以上押した物理確認を必須とし、受理後は一度ボタンを離すまで再承認しない。本体はUSB切断/取外し後に所有権を回復し、確定`.AGE`だけを削除する。`.TMP`と他の名前は保全する。

## 理由

- 同一バイナリの一括工場書込みにでき、購入者によるはんだ、配線、デバッガ書込みを不要にする。
- 公開鍵だけを端末へ置く暗号化要件を維持する。
- MSCの録音領域をread-onlyにして、取り込み時の破損面を減らす。
- HIDはmacOS、Windows、Linuxの標準USB class driverを使用できる。ただし実機3 OS試験を通るまでは対応済みと主張しない。

## リリースゲート

- 実装済みのHID descriptor、登録protocol、内部flash二段階commit、write-once、recipient readback、ホストCLIを実機3 OSで試験する。
- 未登録、CRC不正、flash故障、乱数故障では録音しない。
- 物理確認のない初回登録、登録済み個体への別鍵上書き、MSC WRITE(10)、物理確認のない消去を拒否する。初回登録と削除のボタン2秒判定、押下中だけの受理、削除受理後release必須を実機で確認する。
- flash耐久・BOR4・書込み中の電源断を実機で確認する。
- 正式USB VID/PIDを取得し、複合MSC+HID descriptorを実機で確認する。

本決定は購入者の電子組立作業を増やさない。PC上の初回鍵設定は既存要件に含まれる。

Bluetoothは必須でない。以前の「無線チップを一切載せない」という制約は、悪影響がない場合に限って候補比較を許可する条件へ更新する。採用の決定ではない。現STM32U535案はソフトだけでBluetooth対応できない。後日のソフト更新で有効化するにはv1時点で無線SoC、クロック/RF整合/アンテナ、更新手段を設計する必要がある。

## 同条件での比較

| 候補 | 良い点 | 未解決・不利になり得る点 |
|---|---|---|
| 現STM32U535 + 110mAh | USB/SDMMC/ADFを維持、回路の継続利用 | Bluetooth非搭載、後日のソフト追加不可。現LQFP64は大きい。暗号化/短区間確定を含む電流未測定 |
| nRF52840 + 110mAh、無線停止で出荷 | USB/PDMとBluetoothを1チップに搭載し、将来有効化可能 | SDはSPIへ設計変更、クロック/電源/RF/アンテナとファーム変更。無線停止時も録音全体の電流は要比較。チップ寸法だけで全体が小さくなるとは言えない |
| 110mAh→150mAh級 | 同じ平均電流なら約36%長時間化 | 保護/付属コネクタ付き既製パックの寸法・調達未確定。筐体の厚さ/面積/重量が増え得る |

nRF52840のUSB/PDM/Bluetooth仕様はNordic一次資料を参照。旧custom-pcb.mdのCPU実行電流比較は測定条件とパッケージが揃っておらず、そのまま総消費電流の優劣の根拠にしない。無線追加の消費電流がゼロとも、必ず大きいとも断定しない。

## 電池側平均電流による感度計算

使用可能容量を公称の70%と置く設計上の仮定。温度/経年/終止電圧を保証する係数ではない。

| 電池側平均電流 | 110mAh（使用可能77mAh） | 150mAh（仮105mAh） |
|---:|---:|---:|
| 2.0mA | 38.5h | 52.5h |
| 2.5mA | 30.8h | 42.0h |
| 3.0mA | 25.7h | 35.0h |
| 3.5mA | 22.0h | 30.0h |
| 4.0mA | 19.3h | 26.3h |

110mAhで24hの計算閾値は3.208mA。30hは2.567mA、36hは2.139mA、48hは1.604mA。したがって110mAh/2mAを目標にした現予算は36h程度の余裕を狙う方向として合理的だが、実測の裏付けはない。推奨案は**24h必須、30〜36hを設計目標、48hを必須化しない**。

age等の短区間暗号化と頻繁なFAT確定の追加で以前の電力予算は要再評価。SDの内部busyや暗号鍵生成、表示、電源損失を含む電池端電流で比較する。電池寿命のために音声区間を省略して24h達成と扱わない。

## 採用前の判断と相談

同じマイク/保存/暗号/短区間確定条件で、STM32とnRFの録音処理時間・電池端平均/ピーク電流・RAM/Flash・実装面積・調達を比較する。評価ボードの常時LED/デバッガ負荷は分離して記録する。可能なら同じ音声試験素材で確認し、評価ボード差をSoC差と誤認しない。

提案: まず110mAhで30〜36hを狙う。Bluetoothのために厚く/重く/短時間化させない。nRF案が同等以上の録音持続/実装寸法/調達を満たせる証拠がある場合だけ採用候補へ上げる。満たせない場合は有線案を優先し、将来の無線版は基板変更とする。BLE予約用の追加基板やソケットを保険として載せない。

実測で110mAhの24h余裕が不足したときは、録音品質を落とす前に電源/保存処理最適化を行う。それでも不足なら、実際に買える150mAh級パックの外形を示し、サイズ増加をユーザーに相談して決める。今回は相談資料の作成のみでMCU/電池/基板は変更しない。

将来の金属外装にはアンテナ用非金属部または別のRF構造が必要になり得る。Bluetoothの厚さが同じでも平面面積・外観を犠牲にする可能性を含めて比較する。

## 相談後の更新: 保存36時間・Bluetoothを優先検討

ユーザーは充電可能性を踏まえ、電池持ちは24時間超、保存容量は少なくとも36時間分を希望。36時間は充電なし録音時間の必須化ではない。この条件を満たすなら後の基板変更を避けるためBluetooth回路をv1から載せたいという意向。nRF52840等のBluetooth/USB対応SoCを優先評価候補へ上げるが、24時間超の実測・機構・調達成立前に採用確定しない。現STM32回路は比較原本として保持する。

16kHz mono IMA-ADPCM（1024byte/2041samples）の36時間は1,040,356,352byte（約1.04GB）。短区間WAV・age・FS管理分を含めて36時間枠を1.2GBと仮置きしても4GBには余裕がある。1.2GBは実形式と分割長による検証前の設計予算で保証上限ではない。PCM16は4,147,200,000byteで、公称4GBに36時間分は入らない。よって36時間保存の標準は圧縮録音とする。

110mAh、使用可能率70%の仮定では平均3.208mAが24hの閾値。24h超と余裕を狙い2〜2.5mAを目標に維持（計算上38.5〜30.8h）。nRFの電流をこの目標値と同一視しない。無線は初期無効、USB取出し優先。後日のBluetooth同期にはv1でアンテナ/RF/クロック/更新経路を成立させ、無線実装・通信試験・適用要件の確認も必要。単にSoCを交換しただけでは将来対応を保証しない。

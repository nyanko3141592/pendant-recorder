## 層と境界

1. **USB接続**: USB-C接続直後は充電のみ。同期要求は本体の明示操作。録音を停止してファイルを確定・FSを解放した後だけUSB MSCを公開する。OSによる自動マウントの有無を前提にしない。
2. **ドライブの識別/コピー**: ドライブ文字・`/Volumes`・ボリューム名だけに依存せず、仕様化した識別情報で認識する。CLIには手動のパス指定を必須機能として用意する。識別情報は信用の根拠ではなく、未知のUSB内容は未信頼入力として扱う。
3. **ファイル/鍵の相互運用**: 内蔵ストレージは暗号化コンテナ。受信側は公開仕様とテストベクトルに基づいて復号する。識別・鍵ID・バージョン・認証対象・終端・不完全ファイルの扱いを仕様化してから形式を固定する。独自アプリでも同じ鍵と形式で読み出せるようにする。
4. **CLI/ライブラリ**: デバイス列挙、セットアップ、コピー、復号、検証、時刻設定を提供。音声認識・要約は別の任意処理。Pythonスクリプト、GUI、AIエージェントから利用可能にする。
5. **OSアダプター**: マウント検知、安全な取り外し、鍵保管、パッケージ配布だけをOS別実装に隔離する。暗号形式をOS別に変えない。

## CLI契約案

以下は目指すインターフェースであり、現在実行できるコマンドではない。実行ファイル名`pendant`は暫定。

```text
pendant devices --json
pendant inspect --device-path PATH --json
pendant pair --device-path PATH
pendant sync --device-path PATH --output PATH --json
pendant decrypt INPUT --output PATH --key-id ID --json
pendant verify INPUT --json
pendant time set --device-path PATH --json
pendant keys export --key-id ID --output PATH
pendant keys import INPUT
```

- 最新の必須範囲: `sync`は暗号文のコピー・検証・登録鍵での復号を行い、指定したPC側出力先へ通常のWAVを保存する。利用者が「音声を取り出せた」までを一操作で完了する。実行時に出力先が平文音声の保存先であると明示する。暗号文だけの取得は将来の別オプションとし、通常の同期成功と混同しない。
- 文字起こし・要約・外部送信・録音削除を暗黙に実行しない。これらは公式v1ツールの必須範囲外。ユーザーが任意のツールへWAVを渡す。
- `--json`時はstdoutを機械可読な結果専用にし、診断・進捗はstderrへ。結果には`schema_version`、`ok`、結果または安定した`error.code`を含める。秘密鍵・音声・文字起こしを診断ログへ入れない。
- 非対話モードでは入力待ちをせず、物理操作・鍵保管庫の解除・確認が必要なら機械可読エラーを返す。エージェント実行だから確認を迂回しない。
- 終了コード案: 0=成功、1=一般失敗、2=引数/設定不正、3=デバイスなし、4=鍵利用不可/未登録、5=形式/認証失敗、6=ユーザー操作必要。正式版前にコードとJSON Schemaを固定し、OS間で統一する。
- 鍵やバックアップ用パスフレーズをコマンド引数へ直接入れない。端末プロンプト・OS鍵保管庫・明示指定した安全な入力経路を使う。
- コピーは途中ファイルと確定ファイルを分け、検証後に確定する。パスの脱出・シンボリックリンク・サイズ上限・破損入力を検証。成功後も本体の元録音を残す。

## クロスプラットフォーム鍵管理

Mac Keychainは一つのバックエンドであり、公開仕様の必須条件ではない。WindowsのOS保護ストア、LinuxのSecret Service等、各OSの保管方式を検討する。具体API/依存/アクセス制御は実装時に検証して固定する。

ヘッドレスLinuxや鍵保管サービスのない環境では、パスフレーズ保護の可搬鍵ファイルを候補とする。平文保存へ自動フォールバックしない。バックアップ形式は暗号化・KDF・パラメータ・バージョン・鍵IDを仕様化し、異なるOSへ移行できるようにする。OS保管庫の内部形式や非移行可能な鍵だけに依存しない。方式は未確定。

## 形式固定までに必要な成果物

- USB識別、ドライブ内のディレクトリ/ファイル名、デバイス情報と互換性判定のJSON Schema。
- 初回登録の物理確認、既存鍵の変更認証、鍵喪失時の再登録、複数PCの鍵移行に関する状態遷移。
- 暗号化コンテナのバイト単位仕様、認証対象、乱数/nonce、チャンク境界、再起動/切断/終端/改ざんの扱い。
- UTC時刻の符号化・妥当性範囲・更新タイミング。現TIME.TXT案の最終書式。録音IDの安定性と重複取込みの規則。
- 公開してよい固定テスト鍵・合成音のテストベクトル、正例と誤鍵/改ざん/切詰め等の負例。
- 3 OSで同じベクトルを読み、登録→録音→同期→復号→取り外しを確認する互換性テスト。
- バージョン交渉/未対応形式の拒否と移行手順。互換性を壊す変更を黙って行わない。

## 配布

GUIより先にCLIと再現可能なビルド手順を用意する。macOSはHomebrewを第一候補（ユーザーの「ブルー」をbrewと解釈、未確認）。Windows/Linuxは単体アーカイブと導入手順を先に用意し、パッケージマネージャ登録は後から選ぶ。署名/チェックサム/更新方法は配布時に明示する。

現時点でHomebrew formula、Windowsバイナリ、Linuxパッケージ、公開CLIは存在しない。`host/sync_and_transcribe.py`は旧Mac用の平文WAVスタブで、本契約の実装ではない。

## 同期の完了条件（最新ユーザー指定）

公式v1ツールの責務は **本体 → コピー → 認証検証/復号 → PC上の通常WAV** まで。文字起こし・要約・Notion連携は後段の利用例に留め、同期ツールの必須依存にしない。認識モデルの導入やネット接続なしに音声を取得できること。

- 成功結果には、仕様バージョン、録音ID、出力ファイルパス、バイト数、SHA256、取得/既取得/未完了の状態を返す。時刻や音声仕様は検証できたものだけ返す。JSON Schemaは実装前に固定する。
- 対象ファイルが認証検証・WAV検証を通り、出力を確定してから成功を返す。途中ファイルを完成済みWAVとして公開しない。未完了録音の回復結果は明示し、完全成功と区別する。
- 鍵なし・誤鍵・破損・ディスク満杯では成功を返さない。複数録音の一部失敗は非ゼロ終了とファイルごとの結果で示す。
- 再実行で同じ録音を無駄に増殖させず、既存ファイルを無条件で上書きしない。録音IDと検証済みハッシュによる再開/重複処理を仕様化する。
- 同期後も本体の暗号化録音を自動削除しない。出力WAVは平文のため、PC側のアクセス権・ディスク暗号化・バックアップ先に保護を委ねる範囲を説明する。
- 3 OSで接続→明示同期→鍵利用→WAV保存→再実行→安全な取り外しを試験する。ホスト側の自動再生・文字起こし・アップロードはしない。

# 既存形式と電源断時の回収（最新要件・未実装）

独自の音声形式・独自暗号化コンテナを作らない。従来の「バージョン付き暗号化コンテナを新たに定義する」案は撤回する。アプリの操作/JSON結果を公開することと、保存形式を独自開発することを区別する。

## 第一候補

**短い標準IMA-ADPCM WAVを、標準age v1の独立ファイルとして順次確定**する方式を評価する。WAVのfmt/fact/data等は既存仕様に従い、有効サンプル数もfactに記録する。暗号化はageの既存仕様・互換実装を使用し、独自タグや切詰め許容拡張を追加しない。採用にはSTM32上のRAM/Flash・CPU時間・乱数・電流・ライセンスと既存age CLIとの相互運用検証が必要。

初期評価は約5〜10秒の区間で行い、最終値は電流/書込み時間/許容損失で決める。10秒のADPCMは約80KBで、1日8640ファイルになる。ファイル数とFAT更新負荷も評価し、日付等のディレクトリで分散する。ファイル名/時刻情報の露出は別途説明する。

短区間をRAMで完成WAVにしてからageで暗号化する案を優先比較する。平文WAVをSDへ書いてから暗号化/削除してはならない（削除してもSD内部に残り得る）。録音継続のための二重バッファ、暗号化の64KiBチャンク、ADF/SD/USBスタックのRAM総量を実測/リンクマップで確認。10秒区間がRAM不足なら短縮し、仕様を独自化して回避しない。

## 保存と回収

- 区間ごとに独立した暗号化ファイルを作り、最終認証まで書込み、f_closeと下位disk_ioctl(CTRL_SYNC)の実装を確認して確定する。書込み処理中も次の音声を取りこぼさないバッファ設計が必要。
- 名前変更だけを原子的な確定保証としない。起動/同期時に既存ファイルを列挙し、PC側で標準age復号の完了とWAVの妥当性を検査する。途中名でも完全なファイルなら回収対象にできる。
- 確定済み区間は個別に復号・回収する。最後の書込み中区間は欠損する可能性がある。標準ageは終端を認証するため、切れた最後のファイルを正常として復号成功扱いしない。検証を省略して音声を出力しない。
- 正常な低残量検知では早めに録音を停止し、短い最終区間を確定する。ただし突然の電源断でも停止処理が動くと仮定しない。
- 起動時に不完全ファイルを自動削除・初期化しない。コピー/検証結果を完全・未完了・破損・欠落として報告する。連結出力で欠落を黙って詰めない。
- ホストの索引だけに復元を依存させず、独立区間を列挙して再構築可能にする。同期後のPCM WAV生成は従来方針を維持。

**損失上限10秒などは未保証。** RAM内の未確定区間、暗号化/書込み待ち、FATメタデータ、SD NAND内部キャッシュ/FTLがあり、過去の確定済み領域まで影響する可能性がある。f_syncはリスク低減であり、媒体全体の電源断安全性の保証ではない。プリ割当・書込み順序・低電圧停止・電源保持容量も評価し、実機のランダム電源断試験で回収範囲を測定する。

## v1検証

1. 標準ツールで区間WAV生成→age暗号化→age CLI復号→既存音声デコーダで検証。
2. 各バイト位置/チャンク境界で末尾を切り、破損区間を成功扱いしないことと、他の完結区間を回収できることを確認。
3. 検証用電源で録音中/暗号化中/書込み中/close中/ディレクトリ更新中を含むランダム電源断を繰返す。復帰後の音声欠落、時刻、既存区間、FS全体の整合性を記録。
4. セル保護遮断に頼る前の低残量停止、SD busy時の電圧降下を確認。暗号化＋定期確定を有効にして24時間/電流測定を行う。
